# Numerical reference fixtures

The files in `references/` are independent numerical oracles for the extension's production shader paths. The canonical case inventory, input dimensions, integer sample formulas, source hashes, and tolerances live in [`../reference-fixtures.js`](../reference-fixtures.js). [`reference-fixtures.json`](reference-fixtures.json) records the exact generated bytes and external toolchain.

In a repository checkout, run the ordinary offline integrity check with:

```sh
npm run reference:check
```

Regenerate all mpv-backed fixtures on Linux with the audited mpv, libplacebo, FFmpeg, Xvfb, Mesa, and software-OpenGL toolchain recorded in the manifest:

```sh
npm run reference:generate
npm run reference:check
```

The generator and npm commands are repository-only; packaged archives retain this reproduction record, the canonical definitions, and the fixtures used by browser validation. The generator verifies every pinned GLSL source, creates 16-bit big-endian PGM/PPM inputs, runs mpv through `xvfb-run`, captures the rendered `window`, requires a 16-bit RGB(A) screenshot of the exact dimensions, and converts it to raw little-endian RGB16. It rejects shader compilation/execution failures even when mpv exits successfully. Output replacement happens only after every case has completed.

Fixture SHA-256 values are independently pinned in `reference-fixtures.js`. Regeneration refuses to replace an oracle whose bytes differ from that audited digest. Blessing a deliberate numerical change therefore requires review of the rendered difference followed by an explicit canonical digest and provenance update; changing only the generated manifest cannot authorize new bytes.

FSRCNNX, SSimDownscaler, and adaptive sharpen execute their exact pinned upstream GLSL. ArtCNN's repeated float16 feature-selection blocks are not accepted by the mpv-injected Mesa shader preamble, so the generator deterministically selects the shaders' own f32 fallback and requires exactly eight replacements per model. The reference still retains the upstream hook graph, weights, packing, zero-padding behavior, and depth-to-space implementation.

SSimDownscaler uses `correct-downscaling=yes`, `linear-downscaling=no`, and Catmull-Rom scaling at `62×38 → 31×19`. Model references use a structured grayscale `37×23 → 74×46` case so full-frame scoring covers odd dimensions, partial workgroups, and every padded border. Adaptive sharpen uses structured RGB at `37×23`.

The BT.709 extraction and recombination cases are computed CPU oracles rather than mpv screenshots. mpv applies media metadata and its own color-management pipeline, while the extension intentionally uses a fixed BT.709 matrix. Their deterministic source and high-resolution luma inputs remain part of the same manifest.

Raw fixture pixels are tightly packed as `R`, `G`, and `B` unsigned 16-bit little-endian samples in top-to-bottom row order. Model screenshots can differ by a few 16-bit units across nominally gray display channels, so their metadata records the observed spread and validation compares the WebGPU model output's red/luma component against reference red. Score the entire frame.

FSRCNNX and adaptive sharpen can retain values outside `[0,1]` in their floating-point intermediate textures. Their independent references are window screenshots, so the canonical cases explicitly clamp WebGPU readback to the same presentation range before full-frame scoring. The unclamped production intermediates are not modified.
